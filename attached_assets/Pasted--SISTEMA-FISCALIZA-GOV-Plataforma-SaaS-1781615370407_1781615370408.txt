==========================================================
SISTEMA: FISCALIZA.GOV — Plataforma SaaS de Gestão e
Fiscalização de Obras Públicas
==========================================================

## CONTEXTO E OBJETIVO

Desenvolva uma plataforma SaaS multi-tenant completa para 
gestão e fiscalização de obras públicas municipais. O sistema 
deve atender prefeituras de pequeno e médio porte, órgãos de 
controle (TCE, TCU, CGU) e cidadãos via portal de transparência.

O produto é dividido em três grandes superfícies:
1. App mobile para fiscais em campo (modo offline obrigatório)
2. Painel web para gestores e engenheiros
3. Portal público de transparência

==========================================================
## STACK TECNOLÓGICA OBRIGATÓRIA
==========================================================

### Backend
- Linguagem: Python 3.12+
- Framework: FastAPI (async, alta performance)
- ORM: SQLAlchemy 2.0 com Alembic para migrations
- Banco principal: PostgreSQL 16 com PostGIS (para 
  geolocalização de obras)
- Cache e filas: Redis 7 + Celery (tarefas assíncronas)
- Armazenamento de arquivos: MinIO (compatível com S3) para 
  fotos, vídeos e documentos
- Autenticação: JWT + OAuth2 com integração Gov.br
- Assinatura digital: integração com serviço ITI/Gov.br
- IA: Anthropic Claude API (claude-sonnet-4-6) para análise 
  de obras, geração de relatórios e detecção de riscos

### Frontend Web (Painel + Portal Público)
- Framework: Next.js 14+ (App Router, SSR/SSG)
- Linguagem: TypeScript estrito
- UI: Tailwind CSS + shadcn/ui
- Gráficos: Recharts (curva S, dashboards)
- Mapas: Leaflet.js com tiles OpenStreetMap
- Estado global: Zustand
- Formulários: React Hook Form + Zod

### App Mobile (Fiscal em Campo)
- Framework: React Native com Expo
- Offline-first: WatermelonDB para persistência local
- Sincronização: background sync ao recuperar conexão
- Captura de mídia: câmera nativa com geotag automático
- Mapas offline: react-native-maps

### Infraestrutura e DevOps
- Containerização: Docker + Docker Compose
- CI/CD: GitHub Actions
- Monitoramento: estrutura preparada para Prometheus + Grafana
- Multi-tenant: isolamento por schema no PostgreSQL (um schema 
  por município)
- LGPD: logs de acesso, consentimento e anonimização

## MÓDULOS E FUNCIONALIDADES DETALHADAS
==========================================================

### MÓDULO 1: AUTENTICAÇÃO E MULTI-TENANCY

- Login via e-mail/senha e via Gov.br (OAuth2)
- Perfis de acesso: Administrador Municipal, Gestor de Obras,
  Fiscal de Campo, Engenheiro Responsável, Auditor Externo,
  Cidadão (somente leitura)
- Cada município é um tenant isolado (schema separado no banco)
- RBAC (Role-Based Access Control) granular por módulo
- Registro de todos os acessos com IP, timestamp e ação (audit log)
- Sessões com refresh token, logout remoto de dispositivos
- 2FA opcional via TOTP (Google Authenticator)

### MÓDULO 2: CADASTRO DE OBRAS

Campos obrigatórios:
- Nome e descrição da obra
- Tipo (pavimentação, edificação, saneamento, iluminação etc.)
- Localização: endereço + coordenadas GPS + polígono no mapa
- Empresa contratada (CNPJ validado via API Receita Federal)
- Número e data do contrato, processo licitatório de origem
- Valor contratado original
- Prazo contratual (data início e data fim)
- Fonte dos recursos (FNDE, PAC, Emenda, Tesouro Municipal etc.)
- Responsáveis técnicos com número de ART/RRT e data de validade
- Upload de documentos: contrato, projeto executivo, licenças,
  ART/RRT (PDF com validação de tamanho e tipo)
- Status inicial: Contratada / Em execução / Paralisada / 
  Concluída / Rescindida

Funcionalidades adicionais:
- Cronograma físico-financeiro: upload de planilha ou 
  preenchimento inline com etapas, percentuais e valores por mês
- Visualização em Curva S (planejado vs realizado)
- Geração de QR Code único por obra (para fixação no canteiro)
- Histórico de todas as alterações (quem alterou, o quê, quando)

### MÓDULO 3: GESTÃO DE ADITIVOS CONTRATUAIS

- Registro de aditivos de prazo, valor ou ambos
- Cada aditivo requer: justificativa, número do aditivo,
  data de assinatura, novo valor/prazo resultante
- Fluxo de aprovação: Gestor → Secretário → (se > 25% do 
  valor original) alerta automático ao controle interno
- Histórico completo de todos os aditivos por obra
- Painel comparativo: valor/prazo original vs atual vs 
  percentual de acréscimo
- Alertas automáticos quando aditivo ultrapassa limites 
  legais (25% e 50% conforme Lei 14.133/2021)

### MÓDULO 4: APP DO FISCAL — REGISTRO DE VISITAS

Interface mobile otimizada para uso em campo:

Ao abrir uma visita:
- Seleção da obra (lista das obras sob sua responsabilidade)
- Confirmação automática de geolocalização (deve estar a 
  menos de 500m da obra para registrar — validação configurável)
- Data e hora automáticos (não editáveis para evitar fraude)

Durante a visita, o fiscal registra:
- Fotos: câmera nativa, máximo 20 por visita, comprimidas 
  automaticamente, com EXIF preservado (GPS + timestamp)
- Vídeos curtos: até 3 vídeos de 60 segundos
- Atividades executadas no dia (texto livre + seleção de 
  etapas do cronograma)
- Percentual de avanço físico global da obra
- Percentual de avanço por etapa do cronograma
- Materiais utilizados (tipo e quantidade)
- Número de trabalhadores em campo
- Problemas ou não conformidades detectadas
  - Classificação: Leve / Moderada / Grave / Crítica
  - Prazo para correção (em dias)
  - Notificação automática à construtora
- Condições climáticas (campo de preenchimento rápido)
- Observações gerais e recomendações

Modo offline:
- Todos os dados são salvos localmente em WatermelonDB
- Fotos ficam na fila de upload
- Ao reconectar, sincronização automática em background
- Indicador visual de status de sincronização
- Conflitos são resolvidos com last-write-wins + log de conflito

### MÓDULO 5: BOLETINS DE MEDIÇÃO (BM)

- Fiscal gera BM a partir das visitas do período
- BM contém: período, etapas medidas, percentuais, valor 
  correspondente, fotos vinculadas, observações
- Fluxo de aprovação digital:
  Fiscal → Engenheiro Responsável → Gestor → Pagamento
- Cada aprovação exige assinatura digital (integração Gov.br 
  ou certificado ICP-Brasil)
- Construtora recebe notificação e pode contestar via portal
- Histórico de todos os BMs com status e valores acumulados
- Integração: exportação em formato compatível com 
  TransferênciaGov (SICONV)

### MÓDULO 6: GESTÃO DE DOCUMENTOS

- Upload categorizado: contratos, aditivos, projetos, laudos,
  ART/RRT, alvarás, licenças ambientais, notas fiscais
- Versionamento: cada documento mantém histórico de versões
- Assinatura digital: botão para assinar via Gov.br
- Busca full-text em nomes e categorias
- Compartilhamento seguro com link temporário (para auditores)
- Alerta de documentos próximos do vencimento (ART, licenças)
- Download em lote por obra (ZIP para auditorias)

### MÓDULO 7: NOTIFICAÇÕES E PRAZOS LEGAIS

- Sistema de notificações formais à construtora (email + 
  WhatsApp Business API + registro em tela)
- Cada notificação tem: número sequencial, tipo, prazo 
  de resposta, status (pendente / respondida / vencida)
- Escalonamento automático: se não respondida no prazo,
  sobe para o gestor e depois para o controle interno
- Tipos: Notificação de Não Conformidade, Ordem de 
  Paralização, Solicitação de Documentação, 
  Advertência Formal, Aplicação de Multa
- Histórico de todas as notificações com evidências vinculadas
- Integração de alertas internos: obra paralisada há X dias,
  ART vencendo em Y dias, prazo contratual em Z dias

### MÓDULO 8: INTELIGÊNCIA ARTIFICIAL (Anthropic Claude)

Integrar a Claude API (claude-sonnet-4-6) para:

a) ANÁLISE DE RISCO AUTOMÁTICA:
   - A cada nova visita registrada, enviar contexto da obra 
     para a IA analisar
   - Retornar: nível de risco (baixo/médio/alto/crítico), 
     justificativa, ações recomendadas
   - Detectar padrões: obra atrasada + muitas não 
     conformidades = risco de abandono

b) RELATÓRIO AUTOMÁTICO DE OBRA:
   - Botão "Gerar Relatório com IA"
   - IA recebe: todas as visitas, BMs, notificações, 
     documentos da obra
   - Produz relatório executivo em linguagem formal, 
     pronto para envio ao prefeito ou ao órgão financiador

c) ASSISTENTE DO GESTOR (chat):
   - Chat contextual onde o gestor pergunta sobre suas obras
   - "Quais obras estão atrasadas?" 
   - "Qual construtora tem mais não conformidades?"
   - "Gere um resumo da Obra X para apresentar na câmara"
   - Contexto carregado dinamicamente do banco de dados

d) ANÁLISE DE DOCUMENTOS:
   - Upload de contrato → IA extrai campos principais 
     automaticamente (valor, prazo, partes, objeto)
   - Verificação básica de conformidade contratual

### MÓDULO 9: PORTAL DE TRANSPARÊNCIA PÚBLICA

Página pública (sem login) com:
- Mapa interativo de todas as obras do município
- Filtros: status, tipo, bairro, empresa, fonte de recurso
- Card de cada obra mostrando:
  - Nome, localização, empresa, valor
  - Prazo previsto e status atual
  - Barra de progresso visual
  - Galeria de fotos mais recentes (aprovadas pelo gestor)
  - Linha do tempo resumida
- URL amigável por obra: /obras/reforma-escola-joao-silva
- Compartilhamento em redes sociais
- Feed RSS de atualizações
- Totalizadores do município: 
  "X obras em andamento · R$ Y milhões investidos"

### MÓDULO 10: RELATÓRIOS E EXPORTAÇÕES

- Dashboard principal com KPIs:
  - Total de obras por status
  - Valor total em execução
  - Obras atrasadas (contagem e percentual)
  - Obras com risco detectado pela IA
  - BMs pendentes de aprovação

- Relatórios geráveis em PDF e Excel:
  - Relatório geral de obras do município
  - Relatório de obra individual com linha do tempo
  - Relatório de medições e pagamentos
  - Relatório de não conformidades
  - Extrato para prestação de contas (formato TransferênciaGov)

- Curva S por obra (gráfico interativo planejado vs realizado)
- Exportação completa de obra (ZIP com docs + fotos + relatório)

## MODELO DE DADOS PRINCIPAL
==========================================================

Entidades principais (PostgreSQL):

municipalities (tenants)
├── id, name, cnpj, state, plan_type, created_at

users
├── id, municipality_id, name, email, role, gov_br_id

works (obras)
├── id, municipality_id, name, type, status
├── contract_value, current_value (com aditivos)
├── start_date, end_date, current_end_date (com aditivos)
├── contractor_id, location (PostGIS Point)
├── polygon (PostGIS Polygon — área da obra)
├── funding_source, contract_number

inspection_visits (visitas de fiscalização)
├── id, work_id, inspector_id, visited_at
├── physical_progress_pct, workers_count
├── activities_performed, observations
├── gps_lat, gps_lng, was_offline_created

inspection_photos
├── id, visit_id, file_url, taken_at
├── gps_lat, gps_lng, caption

nonconformities (não conformidades)
├── id, visit_id, severity, description
├── deadline_days, status, resolved_at

measurements (boletins de medição)
├── id, work_id, period_start, period_end
├── total_value, cumulative_value, status
├── approved_by, approved_at

work_addendums (aditivos)
├── id, work_id, type, value_change
├── days_change, justification, signed_at

documents
├── id, work_id, category, file_url
├── version, signed, expires_at

notifications (notificações formais)
├── id, work_id, type, sent_at
├── deadline_date, status, response_text

ai_analyses
├── id, work_id, trigger_event
├── risk_level, analysis_text, created_at

## REQUISITOS NÃO FUNCIONAIS
==========================================================

- Performance: API deve responder em < 300ms para 95% 
  das requisições (exceto geração de relatórios com IA)
- Disponibilidade: estrutura para 99.5% uptime
- Segurança: OWASP Top 10, rate limiting, SQL injection 
  prevention, XSS protection, CSRF tokens
- LGPD: minimização de dados, logs de acesso, direito 
  ao esquecimento implementável
- Escalabilidade: arquitetura permite adicionar novos tenants 
  sem downtime
- Mobile: app funciona 100% offline e sincroniza ao conectar
- Acessibilidade: WCAG 2.1 nível AA no portal público
- Auditoria: todos os campos sensíveis têm log de alteração
  com usuário, timestamp e valor anterior
